<objective>
Fix a data-integrity bug where reading a display property silently corrupts the stored file-size value on the model instance, potentially persisting corrupt data to the database on any subsequent save.

Purpose: Several DocumentosDigitales instance methods (`validar_documento`, `rechazar_documento`, `crear_nueva_version`, and five others) call `self.save()` after business logic. If any code reads `tamano_archivo_legible` before those saves, the in-memory `tamano_archivo` field is corrupted and the corrupted value (e.g., `2.0` instead of `2097152`) is written to the database. The file then appears to be 2 bytes.

Output: A corrected `tamano_archivo_legible` property that operates on a local variable and never touches `self.tamano_archivo`. A unit test that would have caught the original bug.
</objective>

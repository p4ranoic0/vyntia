# Phase 01.1 Plan 04: Two-Phase Document Upload in Onboarding Dialogs Summary

**One-liner:** Two-phase staged-upload pattern (drop -> preview -> pendingDoc -> upload-in-onSuccess) added to Familiar, Academico (3 dialogs), and Laboral constancia dialogs.

## What Was Built

### OnboardingTabFamiliar.tsx
- Added `CompactDropZone` helper (react-dropzone, compact dashed border)
- Added three state variables: `pendingDoc`, `stagedFile`, `stagedFileMeta`/`isDocPreviewOpen`
- Added `getDocTypes()` for parentesco-aware doc type selection (hijo/hija → DNI + partida; conyuge/conviviente → DNI + acta; others → DNI + partida)
- "Documentos (opcional)" section appears only when `form.parentesco` is set — shows applicable doc types
- Each doc type shows a CompactDropZone or a staged-file chip with remove button
- `DocumentPreviewModal` renders outside the add dialog to avoid nesting issues
- `createMutation.onSuccess` calls `subirDocumento(empleadoId, ...)` if `pendingDoc` is set; on failure shows `toast.warning` and preserves the entity record
- `handleDialogClose` resets all staged state on cancel

### OnboardingTabAcademico.tsx
- Added `CompactDropZone` helper (same as Familiar)
- Three independent upload state sets: `certPendingDoc/certStagedFile/isCertPreviewOpen`, `cursoPendingDoc/...`, `tituloPendingDoc/...`
- Each add-dialog (certificado, curso, titulo) has "Documento (opcional)" section at bottom of form
- Cert: `tipo='certificado_estudios'`, Curso: `tipo='certificado_capacitacion'`, Titulo: `tipo='titulo_profesional'`
- Three separate `DocumentPreviewModal` instances (one per dialog type)
- Each mutation's `onSuccess` calls `subirDocumento` if respective `pendingDoc` is set; failure shows `toast.warning`

### OnboardingTabLaboral.tsx
- Removed immediate-upload-on-drop pattern (`handleUploadConstancia` + `uploading` state)
- Kept `useDropzone` but repurposed: `onDropAccepted` now calls `handleFileSelected` (sets `stagedFile` + opens preview) instead of calling `apiClient.post`
- Added `pendingDoc`/`stagedFile`/`isDocPreviewOpen` two-phase state
- When `pendingDoc` is set: shows staged-file chip with remove button instead of dropzone
- "Guardar" button calls `subirDocumento(empleadoId, 'constancia_trabajo', 'laboral', ...)` directly (no separate entity model — the upload IS the record)
- `DocumentPreviewModal` rendered outside the dialog
- Static upload zones (declaracion_jurada, cv, carta_recomendacion) and existing constancia cards with DocumentUploadZone are untouched

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Email uniqueness clash in cross-employee isolation test**
- **Found during:** Task 1 — first test run
- **Issue:** `onboarding_factory()` always creates employees with `correo_personal="nuevo.empleado@test.com"`. Calling it a second time within a test that already uses `onboarding_client` (which itself calls the factory) caused `UNIQUE constraint failed: empleado.correo_personal`.
- **Fix:** Replaced second `onboarding_factory()` call with a direct `Empleado.objects.create()` using a distinct email address.
- **Files modified:** back/tests/test_documentos_digitales_onboarding.py
- **Commit:** 70e1b954

**2. [Rule 3 - Blocking] Missing jsdom dependency for Vitest jsdom environment**
- **Found during:** Task 2 — first Vitest run
- **Issue:** `vitest.config.js` declares `environment: 'jsdom'` but `jsdom` package was not installed, causing `Cannot find package 'jsdom'` errors that prevented all 3 test suites from running.
- **Fix:** `npm install --save-dev jsdom`
- **Files modified:** front/package.json, front/package-lock.json
- **Commit:** a6e6bbd5

**3. [Rule 3 - Blocking] setup.js default import of jest-dom matchers fails in ESM**
- **Found during:** Task 2 — after jsdom was installed
- **Issue:** `import matchers from '@testing-library/jest-dom/matchers'` fails because `@testing-library/jest-dom` v6 does not provide a default ESM export from the matchers entrypoint. Results in `matchers` being `undefined`, causing `expect.extend(matchers)` to throw `Cannot convert undefined or null to object`.
- **Fix:** Changed to `import * as matchers from '@testing-library/jest-dom/matchers'` (namespace import).
- **Files modified:** front/src/test/setup.js
- **Commit:** a6e6bbd5

# Phase 01.1 Plan 05: archivo_url Backend Fix Summary

**One-liner:** Added `archivo_url` SerializerMethodField returning absolute URL to `DocumentosDigitalesSerializer` and `es_version_actual` filter to `DocumentosDigitalesViewSet`, fixing the "Ver documento" button and upload response contract.

## What Was Built

### Task 1 — archivo_url in DocumentosDigitalesSerializer (commit 7c5d7834)

Added `archivo_url = serializers.SerializerMethodField()` to `DocumentosDigitalesSerializer` with `get_archivo_url()` method that:
- Returns `request.build_absolute_uri(obj.archivo.url)` when request context is available (standard DRF API call)
- Falls back to `obj.archivo.url` (relative path) when no request context (e.g. admin introspection)
- Returns `None` when no file is attached

Added `"archivo_url"` to `Meta.fields` immediately after `"archivo"`.

**Why:** The frontend `DocumentInfo` type has `archivo_url?: string`. The guard `existingDoc.archivo_url` was always falsy because the field didn't exist in the serializer output. Without it, the "Ver documento" button never appeared.

### Task 2 — es_version_actual filter + subir_documento archivo_url (commit 523b6eb5)

**Part A:** Added `es_version_actual` query param filter to `DocumentosDigitalesViewSet.get_queryset()` after the `origen` filter block. Accepts `"true"` or `"false"` — maps to `filter(es_version_actual=True/False)`. When param is absent, no filter is applied (backward-compatible).

**Part B:** Added `"archivo_url": request.build_absolute_uri(doc.archivo.url) if doc.archivo else None` to `OnboardingViewSet.subir_documento` success response data dict.

`subir_foto` already had `archivo_url` in its response — verified present, no change needed.

## Gaps Addressed

- **GAP-02:** `DocumentosDigitalesSerializer` now includes `archivo_url` in every document response — fixes the "Ver documento" button on the onboarding document tab.
- **GAP-05:** `OnboardingViewSet.subir_documento` response now includes `archivo_url` — matches `UploadDocumentResponse` frontend type.

**Test:** As an onboarding employee, upload a document and have it approved. Then upload another that gets rejected.
**Expected:** The corresponding section badge updates to "En revisión" → "Observado" (after rejection). After all docs approved: "Completo".
**Why human:** Status derivation from `docs` array requires live document state from the backend.

#### 3. "Ver documento" Button — PDF and Image Preview

**Test:** As an employee with a previously uploaded DNI PDF, open the Personal tab. Click "Ver documento" on the DNI card.
**Expected:** A modal opens showing the PDF in an `<iframe>`. "Enviar documento" button is absent. "Cerrar" button is present and closes the modal.
**Why human:** Requires actual uploaded file URL and browser rendering of the iframe/image.

#### 4. Two-Phase Upload in Familiar Dialog

**Test:** Open "Agregar dependiente" dialog. Select parentesco "hijo/a". Drop a PDF file into the upload zone.
**Expected:** DocumentPreviewModal opens. Clicking "Enviar documento" stages the file (filename chip appears). Clicking "Guardar" creates the familiar record AND uploads the document. If doc upload fails, a warning toast appears but the familiar record is preserved.
**Why human:** Requires end-to-end interaction with the dialog, file drop, and mutation flow.
